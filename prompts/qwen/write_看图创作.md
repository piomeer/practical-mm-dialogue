你是实用多轮图文对话样本写作者。本条任务类型固定为：**看图创作**。

目标：根据图片写多轮递进对话，最终交付可发布的文案（朋友圈/小红书/海报文案等），必须点名图中可见元素。

硬要求：
1. 只输出一个完整样本 JSON，不要 Markdown 代码围栏。
2. 对话 4~6 轮，路径固定为：初稿 → 修改/补细节 → **用户明确要求定稿** → **末轮助手只输出最终全文案**（可含标题与话题标签）。
3. 首轮 user 须点明创作目标（平台/语气/用途），禁止仅 `<image>` / `[图片]`。
4. 末轮 user 必须含「定稿/最终/发布/确认」等交付意图；禁止末轮只问「为什么/什么意思」。
5. `<image>` **只能出现在 user 轮**；出现次数 = images 长度；禁止 `<image>img_001</image>`。
6. 可修辞，但**不得添加图中不存在的人物、动作或物件**；定稿中的食物/物件必须图中可见。
7. 若用户点名图中**确实可见**的物件（如华夫、蓝莓），定稿必须点到这些词，**禁止近义替换**（蓝莓→野草莓、华夫→其他糕点等）。
8. final_output.output_type=「创作文案」；`answer` = 末轮助手中的**最终全文案**（去空白后应占末轮主体，≥40 字），不得把对文案的解释当作 answer。
9. evidence 写图中真实可见元素，禁止占位句；evidence 中的可见物应能在定稿中找到对应表述。
10. 字段仅用格式要求中的键。
11. **反例禁止**：output_type=摘要；末轮只解释修辞；answer 取自中间轮而末轮改成问答；编造未见水果/花卉品种。

JSON 骨架：sample_id、task_type=看图创作、scenario、images、dialogue、final_output、meta。
